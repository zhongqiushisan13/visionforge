# 故障排查

> 按症状查。每条给「现象 → 原因 → 处理」，不确定就先看 `logs\runtime.log` 和任务浮窗的最后几行。

## 启动与界面

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击毫无反应 | WebView2 运行时缺失 | 用 `VisionForge.exe --browser`，或安装 WebView2 Runtime |
| 提示「已有实例在运行」 | 单实例保护 | 切到已有窗口；要强制新开先退掉旧进程 |
| 页面空白 | 前端 JS 报错 | 打开 DevTools 看 Console；一般是缓存了旧 `app.js`，Ctrl+F5 |
| 端口被占 | 8765 被别的程序占用 | 程序会自动换端口；固定端口就加 `--port 8767` |
| 打开提示 401 | 直接访问了 `/api/*` 而不是页面 | 访问 `http://127.0.0.1:8765/`，让服务端注入 token |
| 所有接口 400「非法 Host」 | 用了非回环地址访问 | 只支持 `127.0.0.1` / `localhost` / `[::1]` |

## 模型与网络

| 现象 | 原因 | 处理 |
|---|---|---|
| 401 | Key 不对或没带 | 重新粘贴 Key；测通道确认 |
| 403 | 账号无该模型权限 / 欠费 | 厂商后台开通或充值 |
| 404 + `model not found` | 模型名错或已下线 | 换模型名；国内厂商注意大小写 |
| 429 | 限流 | 等一会；程序会自动退避重试 3 次 |
| 000 / 超时 | 没到厂商 | 检查代理节点、DNS、防火墙 |
| 502 `CONNECT tunnel failed` | 代理拒绝转发该域名 | 代理规则里放行；或换全局模式 |
| 本地 Ollama 报连接失败 | 请求被塞进代理 | v1.2.1 起已自动绕过；旧版请升级 |
| 返回「只返回了思考内容」 | 思考型模型把预算吃光 | 调大 `max_tokens` 或换非思考模型 |
| 剧本 JSON 解析反复失败 | 模型不稳定 / 输出被截断 | 换模型或调大 `max_tokens`；程序会自动回炉一次 |

## 出片

| 现象 | 原因 | 处理 |
|---|---|---|
| 所有镜头都是渐变卡片 | 没配关键帧 / 镜头通道 | 正常降级；配 ComfyUI 或云端 Key 即可 |
| 镜头全失败 | 通道配置错 | 设置页「测通道」，看链上有谁 |
| ffmpeg 报 `3221225477` | PATH 上另一套 ffmpeg 崩溃 | 打包版优先用内置；也可 `VF_FFMPEG=` 指定 |
| 字幕是方框 | 字体缺中文 | 设置里改 `Microsoft YaHei` |
| 导出很慢 | 编码器选错 | 设置里改 `h264_nvenc`（N 卡）/ `h264_qsv`（Intel） |
| 成片比素材短 | 转场重叠 | 正常；要精确时长就多用硬切 |
| 某一镜一直 queued | ComfyUI 队列有别的任务 | 看 `/queue`，或重启 ComfyUI |

## 本地模型

| 现象 | 原因 | 处理 |
|---|---|---|
| CUDA out of memory | 分辨率/并发过高 | 降到 512×288，`VF_WORKERS=1` |
| 报 `Value not in list ckpt_name` | 工作流里的 checkpoint 不存在 | 放一个 SDXL，或改工作流 |
| 加载 GGUF 直接报错 | 自定义节点补丁被升级覆盖 | 重打 H3 兼容补丁（见第 5 页末） |
| 出片是纯色/黑屏 | VAE 与模型不匹配 | 核对 VAE 文件名 |
| 尾帧卡住 | 帧数不在 4n+1 | 程序已自动对齐；自定义工作流需自己处理 |

## 其他

| 现象 | 原因 | 处理 |
|---|---|---|
| 自检一直转圈 / 启动卡住 | 受限环境删不掉子进程登记文件 | 设 `VF_NO_CHILD_REGISTRY=1` 后重启 |
| 切了语言没生效 | 词库未加载 / 缓存 | 刷新页面；看 Network 里 `i18n/xx.json` 是否 200 |
| 项目列表少了一个 | `project.json` 损坏 | 看该目录是否还有 `project.json`；从备份恢复 |
| 磁盘涨得很快 | 关键帧/镜头/中间产物累积 | 删整个项目目录，或在项目里清理 `cache/` |

## 排查顺序（省时间版）

1. **先看任务浮窗最后 3 行** —— 90% 的答案在这
2. **再看 `logs\runtime.log`** —— 后端异常会写这里
3. **设置页「测通道」** —— 区分「配置错」和「网络错」
4. **`curl` 同一地址** —— 区分「程序错」和「环境错」

```bash
# 例：确认厂商是否可达（不需要真 Key，401 就说明通了）
curl -s -o /dev/null -w "%{http_code}\n" https://api.deepseek.com/v1/models
```

## 原理：为什么错误要分「可重试」

程序把异常分成两类：

- **可重试**：超时、429、5xx、轮询抖动 → 退避重试，最多 3 次
- **不可重试**：401/403、模型不存在、敏感词 → 立刻失败并说明原因

如果统统重试，Key 错了会白等半小时；如果统统不重试，网络抖一下整片就废。分类是省钱和省时间的分界线。

## 原理：为什么日志里能看到警告却看不到报错

很多失败是「降级」而不是「崩溃」：ComfyUI 出图失败会退回占位图，TTS 失败会退回 edge-tts。这些都记成 warning，因为流程还在往前走。真正的致命错误才会终止任务并标红。所以**看到成片质量不对时，先去设置页看「最近警告」**。
