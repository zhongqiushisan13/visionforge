# 成本与预算

> 这里的金额是**估算值**，用来踩刹车，不是账单。真实扣费以厂商后台为准。

## 操作

### 1. 设一个上限

设置页「单项目预算上限（元，0 = 不限）」，或环境变量：

```bash
VF_BUDGET=50
```

超过上限后，剧本、镜头、配音这些**付费调用会在发请求前被拒绝**，并明确报错。本地通道（ComfyUI / Ollama / 占位）不计费，照常运行。

### 2. 改单价

默认单价是保守估计：

```json
{"deepseek": 0.05, "minimax_video": 3.0, "minimax_tts": 0.1,
 "comfyui": 0.0, "local": 0.0, "mock": 0.0}
```

按你的实际套餐改：

```bash
VF_PRICES={"deepseek":0.02,"minimax_video":2.2,"minimax_tts":0.08}
```

### 3. 看花在哪了

「成片」页右栏「成本小结」：已发生金额、调用次数、最近几条明细。「导出」会生成一个 txt。

更细的账在 `projects/<项目>/project.json` 的 `meta.costs` 里，每条记录包含时间、提供方、用途、估算金额。

### 4. 典型成本量级

| 项目 | 估算 |
|---|---|
| 60 秒片，10 镜，云端剧本 + 云端镜头 + 云端配音 | 约 ¥30~35 |
| 同上但剧本走本地 Ollama | 约 ¥31（省不了多少，剧本本来就便宜） |
| 同上但镜头走本地 H3 | 约 ¥2（只剩配音） |
| 全本地 + edge-tts | ¥0 |

镜头是大头，剧本是小头。想省钱优先把镜头挪到本地。

## 原理（为什么这么算）

### 为什么先预留再记账

一次镜头调用可能跑 10 分钟。如果等成功后再记账，这段时间里连开几个任务就能突破上限。做法是：

1. 调前按「单价 × 时长」预留一笔
2. 成功后按实际时长结账，多退少补
3. 失败则释放预留

这样并发场景也不会超支。

### 视频为什么按时长估

H3 的计费口径是「生成秒数」。程序在提交任务时就把 `duration` 记进 `billable_seconds`，所以哪怕任务失败，也能看到「本可以花多少」。

### 为什么本地通道记 0 元

ComfyUI 和 Ollama 消耗的是电和显卡折旧，没有按次账单。记 0 元不是假装免费，而是让预算护栏只拦真正的付费调用。

### 为什么估价一定会偏

- 厂商按 token / 秒计费，程序只能按次或按时长粗估
- 不同模型价差几十倍，默认单价只是中间值
- 缓存命中、阶梯价、汇率都不在估算里

**所以真正的兜底是在厂商后台设硬额度。** 程序里的预算只是第一道闸。

### 成本记录会不会泄露 Key

不会。记录里只有提供方名称、用途、金额和 token 数，不含密钥。`project.json` 可以放心分享。

## 常见问题

**预算还有余额却被拦了**：并发任务会各自预留，短时间可能看起来「明明没花完」。等前面的任务结账即可。

**想临时突破上限跑一次**：设置里把 `VF_BUDGET` 改成 0（不限），或调大数值。改完不用重启，下次调用生效。

**金额和账单差很多**：正常。拿真实账单校准 `VF_PRICES`，估领会越来越准。
