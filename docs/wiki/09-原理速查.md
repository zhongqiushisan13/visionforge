# 原理速查（架构与数据流）

> 这一页不教操作，只回答「它到底怎么运转的」。看完能自己判断问题出在哪一层。

## 一、整体形状

```
┌─────────────────────────────────────────────┐
│ WebView / 浏览器                             │
│   页面只访问 127.0.0.1:8765，带 token        │
└──────────────────┬──────────────────────────┘
                   │ HTTP（同源、带 X-VF-Token）
┌──────────────────▼──────────────────────────┐
│ 本地 FastAPI（videoforge/web/server.py）     │
│   /api/*        路由、校验、任务提交         │
│   JobManager    单任务执行、日志流、进度     │
│   /media/*      项目素材（需 token / Cookie）│
└──────┬───────────────┬──────────────┬───────┘
       │               │              │
┌──────▼──────┐ ┌──────▼──────┐ ┌─────▼───────┐
│ 编剧层      │ │ 镜头层      │ │ 剪辑层      │
│ llm.py      │ │ providers/  │ │ encode.py   │
│ 3 种协议    │ │ 云端/本地   │ │ editing.py  │
└──────┬──────┘ └──────┬──────┘ └─────┬───────┘
       │               │              │
   厂商 HTTPS      厂商 HTTPS/环回    ffmpeg 子进程
```

关键点：**只有后端出网**。界面拿不到 Key，也拿不到厂商原始响应。

## 二、一次任务的生命周期

以「一键成片」为例：

1. 前端 `POST /api/projects/{slug}/actions`，body 里带 `action=all`
2. `_guard_busy()` 检查有没有别的任务在跑（同一时间只允许一个重任务）
3. `JobManager` 开线程执行，接口立刻返回 `job_id`
4. 前端每 1.4 秒 `GET /api/jobs/{id}?since=N` 拉增量日志
5. 执行链：`plan → keyframes → voice → clips → assemble`
6. 每步结束都写 `project.json`
7. 状态变 `done` / `failed`，前端刷新看板

`JobManager` 的日志是**增量**的（`since` + `log_total`），所以任务跑一小时，前端也不会拉一坨历史。

## 三、数据模型

一个项目 = 一个目录 + 一个 `project.json`：

```
Project
├─ title / brief / aspect / resolution / fps
├─ script { logline, synopsis, beats[], characters[], style_prompt }
├─ shots[] { id, duration, prompts, status, seed, clip, audio, 剪辑参数… }
├─ progress { rendered, voiced, failed, duration }
└─ meta { costs[], final_duration, final_size_mb }
```

镜头状态机：

```
pending ──► keyframe ──► rendered ──► voiced
   │            │            │
   └────────────┴────────────┴──► failed
   └──────────────────────────► skipped（手动停用）
```

状态是幂等的：重跑某一步只看当前状态，不会重复做已完成的事。

## 四、编剧层：三协议一接口

```
Writer ──► LLMClient.chat(messages)
                │
                ├─ openai    : {model, messages, response_format}
                ├─ anthropic : {model, system, messages, max_tokens}
                └─ gemini    : {contents, systemInstruction, generationConfig}
                │
                ▼
        归一化成 {role, content} + usage
```

业务层只认「messages 进、文本/JSON 出」。所以换厂商不影响 `writer.py` / `director.py`。

JSON 可靠性三道：

1. 提示词里硬约束（只输出 JSON）
2. 协议层尽量用原生 JSON 模式（OpenAI / Gemini）
3. 解析器容错 + 失败回锅重修一次

## 五、镜头层：同步与异步

- **同步**（ComfyUI 出图）：`POST /prompt` → `prompt_id` → 轮询 `/history` → 下载
- **异步**（云端 H3）：`POST /v2/video_generation` → `task_id` → 轮询 query → 下载
- **本地 H3**：同一个 ComfyUI 轮询模型，节点换成 H3

共同点：**都不在 HTTP 请求里等结果**。任务与请求解耦，才能跑到分钟级。

轮询的节奏是「固定间隔 + 超时上限 + 抖动容忍」：网络抖一下只告警，不终止。

## 六、剪辑层：一次 filtergraph

合成不是「一段段拼文件」，而是尽量用一条 ffmpeg 命令完成：

```
输入片段 → 统一 fps/分辨率 → 每段的 trim/setpts/滤镜 → xfade 拼接
        → 音频 amix + loudnorm → ASS 烧字幕 → 输出 mp4
```

为什么合并成一条：反复解码编码会掉画质，也慢。代价是命令很长，出错时日志不容易读——所以关键参数都会打进任务日志。

## 七、安全模型

| 面 | 做法 |
|---|---|
| 本地 API | 随机 token（`run/token`）+ Host 白名单，防 DNS rebinding |
| 素材 | `/media/*` 需同源 Cookie 或 token，外部网页读不到 |
| 密钥 | 只存 `%APPDATA%`，ACL 收紧，接口只回掩码 |
| 出网 | 直连厂商或用户自己的代理，无中转服务器 |
| 子进程 | 登记到 `run/child-*.json`，崩溃后下次启动清理 |

`VF_ALLOW_UNSAFE_API=1` 可关闭 token 校验，**只用于自动化测试**，正常使用别开。

## 八、降级链（为什么缺东西也能跑）

| 环节 | 优先级 |
|---|---|
| 剧本 | 云端模型 → 本地 Ollama → 内置示例分镜 |
| 关键帧 | ComfyUI → 本地占位图 |
| 镜头 | 云端 H3 → 兼容网关 → ComfyUI 工作流 → 占位片 |
| 配音 | MiniMax T2A → edge-tts → 静音 |

原则：**能降级就不阻塞**。所以「没配 Key 也能出片」，只是质量降一档。

## 九、并发与资源

- 重任务全局串行（一个任务在跑时接口返回 409）
- 任务内部可并发：`VF_WORKERS` 控制镜头并发生成
- 本地模型建议 `VF_WORKERS=1`：单卡并发只会互相抢显存
- ffmpeg 子进程有登记与回收，避免崩溃后留下孤儿进程

## 十、模块地图

| 文件 | 职责 |
|---|---|
| `videoforge/config.py` | 四层配置合并（env / config.json / 环境变量 / 覆盖） |
| `videoforge/llm_providers.py` | 厂商注册表（11 家） |
| `videoforge/llm.py` | 三协议客户端、重试、JSON 抢救 |
| `videoforge/pipeline/writer.py` | 两段式编剧 |
| `videoforge/pipeline/director.py` | 调度：关键帧 → 配音 → 镜头 → 合成 |
| `videoforge/providers/` | 云端 H3、ComfyUI、ComfyUI 视频、TTS、占位 |
| `videoforge/editing.py` | 剪辑参数、转场/滤镜定义、时间线计算 |
| `videoforge/encode.py` | ffmpeg 封装、编码器探测 |
| `videoforge/web/server.py` | 本地 API |
| `videoforge/web/jobs.py` | 任务与日志流 |
| `videoforge/web/static/` | 前端（原生 JS + i18n 词库） |

## 十一、设计取舍

| 选择 | 代价 | 换来了什么 |
|---|---|---|
| 零构建前端 | 不能用框架生态 | 单文件可调试、无 node 依赖 |
| 中文原文当 i18n key | 改文案会牵连翻译 | 漏翻自动回退、代码可读 |
| 状态全落 JSON | 文件会变大 | 断点续跑、可手工修 |
| 任务串行 | 不能同时跑两个项目 | 避免抢显存、账目清楚 |
| 估算计费 | 不等于真实账单 | 调用前就能踩刹车 |
