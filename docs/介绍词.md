# VisionForge 介绍词

> 版本 v1.1.1 ｜ 定位：本机运行的 AI 视频编导台 ｜ 许可：MIT

---

## 一、30 秒电梯稿

VisionForge 是一个跑在你本机的 AI 视频生产工具。你写一句需求，它把这句话拆成剧本、分镜、关键帧、镜头、配音，最后用 ffmpeg 合成为一条带字幕和转场的成片；不满意的地方，可以在时间线上手动改，也可以直接说一句"全部调成黑白，第 2 镜 1.5 倍速"。

它和"调一次 API 弹一段视频"的玩具最大的区别是：**它是一条有状态、可断点续跑、可单镜重拍的生产线**，而且整条链路都能换成本地模型——没有 API Key 也能出片。

## 二、3 分钟完整介绍（可直接照读）

大家好，这个项目叫 VisionForge，一句话概括：**把"我要一个 60 秒的片子"变成一条能反复修改、能自己出片的流水线。**

先说它解决什么问题。现在生成视频的模型不少，但真正要交一条片子，卡人的从来不是"生成一个 5 秒镜头"，而是这四件事：分镜怎么切、镜头之间怎么接、音画怎么对齐、哪一条不满意怎么只重做那一条。所以我没有做一个"文生视频按钮"，而是做了一个**编导台**：模型负责生成，系统负责调度、记录状态、处理失败、保证能重来。

它的运作原理是六段流水线。

**第一段，编剧。** 你输入一句需求，DeepSeek 分两步工作：先出大纲——人物、节拍、情绪、风格锚点；再出分镜表——每条镜头的时长、运镜、中英文字幕、英文画面提示词。这一步强制 JSON 输出，解析失败会重试，再失败降级成本地示例分镜，不会让整条链路卡死。

**第二段，关键帧。** 每条镜头的提示词送进 ComfyUI 出首帧图。这里有个细节：工作流里没有 LoRA 节点时，系统会新建一个 LoRA 节点，并把 checkpoint 的所有下游连接重新接过去——也就是说你不用为了这个工具去改自己的出图工作流。

**第三段，镜头。** 首帧图加提示词送去生成视频。这一步有四条通道，按配置自动装配：MiniMax H3 云端、本地 H3 兼容网关、ComfyUI 视频工作流、以及没有模型时的本地占位片。云端的部分是异步任务：提交、轮询、下载，错误码会被翻译成人话。

**第四段，配音。** 三级兜底：MiniMax T2A、免费的 edge-tts、静音。**关键设计是配音先于定剪**——先用真实音频长度确定每条镜头的时长，再去合成。反过来做就一定会音画错位，这是很多同类工具翻车的地方。

**第五段，合成。** ffmpeg 分四步：逐镜头归一化（分辨率、帧率、变速、调色、镜像、音量）→ 按转场链拼接（11 种真转场，带时间轴重叠计算）→ 混音轨（配音对位、BGM 压到 18%、响度归一）→ 烧字幕（ASS，中文不会出方块）并加 faststart。

**第六段，状态与重跑。** 每条镜头都有独立状态：待生成、已出图、已出片、失败、停用。所有中间产物有缓存，缓存键是"时长 + 入点 + 转场"的指纹。所以改一条字幕不会重算全片，重拍一条镜头也只影响那一条。

配置这块，我刻意做成"能跑起来优先"，分三层：`.env` 管密钥，`config.json` 管本机参数，环境变量可以临时覆盖。首次启动会自动体检——CPU、内存、显卡、ffmpeg 编码器、中文字体、WebView2、本地服务是否在线——然后把推荐值写进 `config.json`。这里有个坑值得单说：`ffmpeg -encoders` 里列出 NVENC 不代表能用，编译时带了就有，虚拟机和没 N 卡的机器照样列；所以判断方式是**真跑一帧编码**，跑通才算可用。

v1.1.1 补的是"本机不等于天然安全"：本地 API 默认带随机 token 和 Host 校验，密钥改写到用户目录而不是 exe 旁边；同时给云端调用加了单项目预算护栏，重拍和重试都会记账，超限会在真正花钱前拦下来。

最后是边界，我把它写清楚，因为藏着掖着最后都会变成"说好的呢"。

第一，**未签名的 exe 会被 SmartScreen 拦一下**，点"更多信息 → 仍要运行"；这是省钱，不是病毒。

第二，**别解压到 `C:\Program Files`**，程序把配置和工程写在 exe 同级目录，那里没写权限就会瘸。

第三，**它是绿色版，不是安装包**：解压即用，删目录即卸载，没有快捷方式也没有自动更新。

第四，**云端模型调用需要你自己的 Key**，没配 Key 时新建项目会自动勾选 MOCK，用占位素材跑通全流程——它不会假装在调模型。

第五，**它不追平剪映**。多轨、关键帧动画、蒙版、抠像、卡点这些没做，因为那需要图层树和关键帧曲线，不是加几个滤镜参数能糊过去的。它的定位是：AI 生成 + 单轨精修，精修到极致请导出素材去剪映。

一句话收尾：**这不是一个"生成视频"的工具，是一个"能把片子改到能交"的工具。**

## 三、运作原理（技术版）

### 3.1 流水线与状态机

```
brief ──▶ 剧本大纲 ──▶ 分镜表 ──▶ 关键帧 ──▶ 镜头 ──▶ 配音 ──▶ 合成 ──▶ 成片
             │            │           │         │        │        │
             └────────────┴───────────┴─────────┴────────┴────────┘
                        所有中间态写进 project.json，逐镜头记录
```

| 阶段 | 实现 | 输入 | 输出 | 失败时的行为 |
|---|---|---|---|---|
| 立项 / 剧本 | DeepSeek 两段式（大纲 → 分镜表），强制 JSON | 一句 brief | `project.json` + shots | 重试 → 换模型 → 本地示例分镜 |
| 关键帧 | ComfyUI `/prompt` 队列，LoRA 自动注入 | 英文 image_prompt | `keyframes/S01.png` | 降级为占位图，不阻塞 |
| 镜头 | MiniMax H3 / 本地网关 / ComfyUI 视频 / 占位 | 首帧 + 提示词 + 时长 | `clips/S01.mp4` | 逐镜头重试，失败不影响其它镜头 |
| 配音 | MiniMax T2A → edge-tts → 静音 | 台词 `dialogue` | `audio/S01.mp3` | 一级失败下一级，最终静音保时长 |
| 合成 | ffmpeg 四阶段 | 片段 + 音频 + 字幕 | `output/xxx.mp4` | 缺片段的镜头标记 excluded，不中断 |
| 交付 | 前端播放 + 下载 + SRT | 成片 | MP4 / SRT | — |

### 3.2 合成四阶段（最容易出问题的地方）

1. **归一化**：统一分辨率、像素格式 `yuv420p`、帧率、SAR；应用变速（`setpts`）、调色（`eq` / `colorbalance` / `hue`）、镜像、音量。
2. **拼接**：无转场走 `concat` 快速通道；有转场走 `xfade` 链，并按"重叠时长"重算每段起点与总时长。
3. **声轨**：逐镜头音频按最终时间轴对位，BGM 压到 18% 并淡出，`amix` 后 `loudnorm` 归一到 -16 LUFS 附近。
4. **字幕与封装**：ASS 烧录（带描边、中文 CJK 字体），`+faststart` 便于网页秒开。

### 3.3 三个关键设计决策

**① 配音先于定剪。**
镜头时长不是拍脑袋定的，是先拿到音频真实时长再锁。音画错位的根源几乎都是"先定时长后配音"。

**② 缓存指纹而不是时间戳。**
归一化缓存的键是「时长 + 入点 + 转场 + 变速」，改字幕不会触发重算，改时长才会。这决定了"改一句台词要不要等十分钟"。

**③ 每一环都能降级。**
ComfyUI 不在线 → 占位图；没有视频模型 → 占位片；TTS 不可用 → 静音；LLM 不可用 → 示例分镜。降级不是遮丑，是让你在只配了一半环境的机器上先把流程跑通。

## 四、配置

### 4.1 配置层级（后者覆盖前者）

```
.env（密钥、通道开关）
  └─ config.json（本机参数：分辨率、编码器、并发、字体；首次启动自动生成）
       └─ 环境变量（临时覆盖，如 VF_MOCK=1）
            └─ 命令行参数（--port / --serve / --mock）
```

### 4.2 三条路线

| 路线 | 配置量 | 适用 | 代价 |
|---|---|---|---|
| **零成本试跑** | 什么都不填，新建项目勾 MOCK | 验证流程、做 UI 演示 | 占位片，非真画面 |
| **云端** | `DEEPSEEK_API_KEY` + `MINIMAX_API_KEY` | 要成品质量 | 按量计费 |
| **全本地** | 本地 LLM + ComfyUI + 本地 H3 网关 | 隐私、零边际成本 | 要显卡，速度看硬件 |

### 4.3 关键环境变量

```env
# 编剧大脑：任何 OpenAI 兼容端点
DEEPSEEK_MODE=auto                 # auto / cloud / local
DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash

# 镜头生成：云端 / 本地网关 / ComfyUI 工作流
MINIMAX_MODE=auto                  # auto / cloud / local / comfyui / mock
MINIMAX_API_KEY=
MINIMAX_BASE_URL=https://api.minimax.io
MINIMAX_SUBMIT_PATH=/v2/video_generation
MINIMAX_QUERY_PATH=/v2/query/video_generation/{task_id}
MINIMAX_VIDEO_WORKFLOW=            # 填 workflows/ 下的文件名即走 ComfyUI 出片

# 关键帧
COMFYUI_BASE_URL=http://127.0.0.1:8188
COMFYUI_WORKFLOW=txt2img_api.json
COMFYUI_DEFAULT_LORA=

# 渲染
VF_ENCODER=auto                    # auto / libx264 / h264_nvenc / h264_qsv / h264_amf
VF_MOCK=0
VF_BUDGET=20                       # 单项目估算成本上限（元），0=不限
```

### 4.4 首次自动配置探测什么

| 探测 | 用途 |
|---|---|
| CPU 核数 / 内存 / 磁盘余量 | 决定并发数；内存 < 8G 自动降到 720p |
| NVIDIA GPU / 显存 | 决定 ComfyUI 出图尺寸（1024×576 ~ 1536×864） |
| ffmpeg 编码器 | **试编码一帧**，选 NVENC / QSV / AMF；失败回落 `libx264` |
| 中文字体 | 选第一个可用 CJK 字体，避免字幕方块 |
| WebView2 | 缺失则退回浏览器模式 |
| ComfyUI / 本地视频网关 | 探活，决定默认链路 |

结果写进 `config.json` 的 `_meta.auto_configured_at`，换机器后可在设置页「重新检测并应用」。

### 4.5 手动剪辑能力（单轨精修）

| 能力 | 范围 |
|---|---|
| 排序 / 入点 / 时长 | 拖拽排序；入点 0~N 秒；1~15 秒 |
| 变速 | 0.25x ~ 4x，含倒放、镜像 |
| 转场 | 11 种：硬切 / 淡入淡出 / 叠化 / 左划 / 右划 / 上滑 / 下滑 / 放大推入 / 黑场 / 白闪 / 圆形展开，每条 0.1~1 秒 |
| 调色 | 7 个预设（电影青橙 / 黑白 / 复古 / 冷 / 暖 / 高饱和 / 原片）+ 亮度 / 对比度 / 饱和度 / 色温 |
| 文字层 | 每条镜头独立标题，顶部 / 居中 / 底部，字号可调，与字幕分开渲染 |
| 声音 | 逐镜头音量 0~200%、BGM 上传与淡出、整体响度归一 |
| 分割 | 在镜头第 N 秒切成两条，入点自动换算（含变速换算） |
| 素材 | 本地视频替换单条 / 导入追加一条 / 上传 BGM |
| AI 指令 | 「全部调成黑白，第 2 镜 1.5 倍速，加叠化转场」→ 直接改参数 |
| 重拍 | 写一句意见，改写中英文提示词 + 换 seed 只重做这一条 |

## 五、注意事项

### 5.1 部署

- **不要解压到 `C:\Program Files`**。配置、工程、日志都写在 exe 同级目录，那里默认无写权限。
- **exe 未签名**，SmartScreen 会拦；选「更多信息 → 仍要运行」。
- **WebView2**：Win10/11 自带；Win7/8 需先装 Runtime，否则自动用浏览器打开。
- **它是绿色版**：解压即用、删目录即卸载，没有安装器、快捷方式、自动更新。
- **端口**：默认 `8765`，被占用会自动顺延；只监听 `127.0.0.1`，且默认启用随机 token 与 Host 校验。不要为了“方便局域网访问”改成 `0.0.0.0`——它不是为公网/局域网共享设计的。

### 5.2 成本

- 云端 H3 按生成时长计费。**先用 MOCK 跑通全流程**，确认分镜和字幕对了，再切真模型，否则你在为调参付费。
- 先用 30 秒短片对账，再上 3 分钟。长片的重跑成本是指数级的。

### 5.3 技术坑（已修，但你要知道它们存在）

| 坑 | 现象 | 处理 |
|---|---|---|
| `xfade duration=0` | 后面所有片段被吞，输出只剩前几段 | 硬切统一给 0.04s 融合 |
| `gradients` 源 `duration=1` | 每条片段只有 1 秒 | 按镜头时长生成源 |
| 本地请求走系统代理 | `127.0.0.1` 被代理劫持，ComfyUI 连不上 | `trust_env=False` |
| 并发写 `project.json` | Windows 下 `Permission denied` | 加锁 + 原子替换 |
| `-t` 位置错误 | 变速镜头被 `tpad` 撑长 | `-t` 放在 `-i` 前做输入裁剪 |
| PyInstaller 路径 | `.env` 和成片写到 `%TEMP%` | 拆 `APP_ROOT`（可写）/ `BUNDLE_ROOT`（只读） |
| pythonnet 漏 DLL | 窗口起不来 | `clr.pyd` + `Python.Runtime.dll` 手工进 binaries |

### 5.4 边界与未验证项

- **未验证**：真实 MiniMax H3 云端调用、真实 ComfyUI 视频工作流（需要你本地有模型和额度）。已验证的是：完整流水线、本地网关协议（用 mock 服务跑通提交→轮询→下载）、错误降级、UI 全流程、打包版出片。
- **不做**：多视频轨 / 画中画 / 多机位、关键帧动画、蒙版与抠像、曲线变速与光流补帧、BGM 卡点、贴纸花字、语音识别自动字幕、数字人。这些需要图层树和关键帧曲线，硬塞假按钮只会在导出时露馅。
- **质量边界**：分镜逻辑依赖 LLM，长片（> 3 分钟）容易节奏散；建议 6~12 条镜头、40~90 秒一段，分段生产再拼。

## 六、常见问答

**Q：没有显卡能用吗？**
能。MOCK 模式出一版占位片，或只接云端 H3；关键帧那一步会降级成占位图。

**Q：一定要有 API Key 吗？**
不一定。剧本可接 Ollama / vLLM，镜头可接本地 H3 网关或 ComfyUI 工作流，配音可用免费 edge-tts。三样都本地，就是零成本。

**Q：能直接发抖音/B 站吗？**
能出 1080p30 H.264 + AAC 的 MP4，规格通用。但它不做平台专属的封面、话题、竖屏安全区适配。

**Q：改了字幕要重新出片吗？**
要重新合成，但不会重算镜头；归一化缓存按指纹命中，通常几十秒。

**Q：和剪映什么关系？**
互补。它负责"从 0 到一条能看的片子"，剪映负责"从能看打磨到能爆"。真要做精修，把素材导出去剪映更划算。

**Q：会开源吗？**
MIT，已经开源。商用、二改、闭源分发都可以，保留版权声明即可。
