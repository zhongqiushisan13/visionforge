# 06 故障排查

先看日志，别猜。日志位置：

| 形态 | 路径 |
|---|---|
| 打包版 | `exe 同级的 logs/runtime.log` |
| 源码版 | 项目根 `logs/runtime.log`（或在终端里直接看输出） |
| 启动即崩 | `logs/startup-error.log` |

## 一、启动相关

| 症状 | 原因 | 处理 |
|---|---|---|
| 双击没反应 | 被杀软拦截 / 缺 WebView2 | 看 `logs/startup-error.log`；装 [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) |
| SmartScreen「已保护你的电脑」 | exe 未签名 | 「更多信息 → 仍要运行」 |
| 窗口白屏 | 静态资源没打进包 / 端口被占 | 换 `--port 8790` 试；看日志里 `serving at` 的端口 |
| 提示「本地服务未在规定时间内就绪」 | 启动超时（杀软扫描慢） | 再点一次；或把解压目录加进杀软白名单 |
| 启动后立刻退出 | 配置写不进去（放 Program Files 了） | 换到 `D:\VisionForge` 这类有写权限的目录 |
| 端口被占用 | 8765 已被别的程序占 | 程序会自动顺延，日志里能看到实际端口 |

## 二、出片相关

| 症状 | 原因 | 处理 |
|---|---|---|
| 画面只有渐变色块 | 没配视频模型，走了占位片 | 正常。去设置配 Key 或本地网关 |
| 成片只有前 3 段 | 历史 bug：`xfade duration=0` 吞片段 | 1.1.0 已修（硬切退化为 40ms 融合），升级 |
| 成片比预期短很多 | 转场重叠叠加 | 10 条 6 秒 + 9 个 0.4 秒转场 = 56.4 秒，属正常 |
| 字幕是方块 | 缺中文字体 | 设置页换字体（微软雅黑 / 思源黑体），或系统装字体 |
| 音画不同步 | 变速后配音没跟着变 | 变速只作用画面；密集台词镜头别超过 1.5x |
| 没有声音 | TTS 全部失败 | 检查网络（edge-tts 要联网）或配 MiniMax Key；日志里会写降级到静音 |
| 成片体积异常小（<1MB） | 编码失败或只有占位 | 看日志里的 ffmpeg 报错，通常是编码器不可用 |
| 合成很慢 | 逐段二次编码 | 换硬件编码器（设置页），或用更短的片子分段跑 |

## 三、模型相关

| 症状 | 原因 | 处理 |
|---|---|---|
| `ComfyUI 连接被拒` | 没启动，或端口不是 8188 | 启动 ComfyUI；确认 `COMFYUI_BASE_URL` |
| 本地服务「明明在跑却连不上」 | 系统代理劫持了 127.0.0.1 | 代码已 `trust_env=False`；若自己改过，检查代理设置 |
| `401 / 403` | Key 错误或没权限 | 设置页「测通道」验证；本地服务不需要 Key |
| `429` | 限额 | 降低并发出图数，或换模型 |
| 分镜总时长和目标差很多 | 时长约束是软约束 | 见下方「节奏不对」 |
| JSON 解析失败 | 模型不支持 JSON 模式 | 自动重试后会退到示例分镜；换支持 JSON 的模型更稳 |

## 四、节奏不对

日志里会出现类似：

```
[warn] 分镜总时长 52s 与目标 18s 偏差较大
```

这是**已知局限**：时长约束写在提示词里，模型不一定遵守，系统只告警不阻断。应对：

1. 目标时长写具体，别用「大概一分钟」
2. 生成后手动删/停用多余镜头（时间线页取消「进成片」）
3. 用「分割」把长镜头拆开，用「时长」压短
4. 长片（>3 分钟）分多段生产，最后拼接

## 五、打包相关

| 症状 | 原因 | 处理 |
|---|---|---|
| 打包后配置写到 `%TEMP%` | 用了包目录推导路径 | 已修：`APP_ROOT`（可写）/ `BUNDLE_ROOT`（只读）分离 |
| 打包后窗口起不来 | `clr.pyd` / `Python.Runtime.dll` 没收集 | spec 里手工加到 binaries |
| CI 报 `UnicodeEncodeError` | Windows runner 是 cp1252 | 脚本里 `reconfigure(encoding="utf-8")` + `PYTHONIOENCODING` |
| CI 报 `No module named 'PIL'` | 生成图标需要 Pillow | 图标已入库则复用；或 `pip install pillow` |

## 六、网络与代理

这个项目的失败案例里，代理占了相当比例：

- **本地服务不要走代理**：`127.0.0.1` 被代理接管时，ComfyUI / 自建网关会「连不上」。代码里已对本地会话关掉 `trust_env`。
- **git push 报 `CONNECT tunnel failed, response 502`**：代理对 `github.com:443` 抽风。重试，或改用 Git Data API 提交（本项目发布时就是这么绕过去的）。
- **下载 Release 资产极慢**：走代理拉几十 MB 常常中途断。能用浏览器就用浏览器。

## 七、提交问题时请附上

1. 操作系统版本 + 是打包版还是源码版
2. `logs/runtime.log` 最后 50 行
3. 复现步骤（点了什么、期望什么、实际什么）
4. 设置页「系统自检」的截图（编码器、字体、WebView2 状态）

没有日志的问题单，排查效率会低一半。
