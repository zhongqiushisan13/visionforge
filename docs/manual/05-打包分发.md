# 05 打包与分发

## 一、本机打包

```bash
python -m pip install pyinstaller
python build_app.py            # 生成到 dist/VisionForge/
python build_app.py --clean    # 先把旧 dist 改名挪开（不直接删）
```

产物：

```
dist/VisionForge/
├── VisionForge.exe
├── _internal/            # 运行时、静态资源、内置 ffmpeg、workflows
├── .env.example
├── README.md
├── config.example.json
├── examples/
├── projects/             # 空目录，运行时写入
└── logs/                 # 空目录，运行时写入
```

打包脚本会把配置模板和示例复制到 exe 旁边——**别手动把 `_internal` 里的东西搬出来**，路径是设计好的。

## 二、改版本号

三个地方要一起改，否则窗口标题、文件属性、页面显示会对不上：

| 文件 | 位置 |
|---|---|
| `videoforge/__init__.py` | `__version__ = "1.1.1"` |
| `build_app.py` | `VERSION_TEXT` 里的 `filevers` / `prodvers` / `FileVersion` / `ProductVersion` |
| `README.md` | 徽章与下载文件名（可选） |

然后 `git tag -a v1.1.1 -m "..."` 并推送，CI 会自动出包。

## 三、发布流程（GitHub Actions）

```
打 tag v* ──▶ Release workflow（windows-latest）
               ├─ pip install -r requirements.txt + pyinstaller + pillow
               ├─ python build_app.py --clean
               ├─ Compress-Archive dist/VisionForge/* → VisionForge-<tag>-win64.zip
               ├─ upload-artifact（保留 90 天）
               └─ action-gh-release 发布
                        │
                        └─▶ Checksums workflow：下载资产 → 生成 SHA256SUMS.txt → 挂回 Release
```

两个工作流的职责边界：

- `release.yml`：构建 + 发布二进制
- `checksums.yml`：给已发布的资产补校验文件（也支持手动 dispatch 补历史 Release）

为什么校验放在 CI：本机走代理拉 58MB 要一小时，runner 上是秒级。

发布说明里必须同时给出：资产文件名、文件大小、`SHA256SUMS.txt` 链接，以及一行示例校验命令：

```powershell
certutil -hashfile VisionForge-v1.1.1-win64.zip SHA256
```

用户机器上的哈希必须与 `SHA256SUMS.txt` 完全一致；不一致就不要运行。

## 四、CI 上踩过的两个坑

| 现象 | 原因 | 处理 |
|---|---|---|
| `UnicodeEncodeError: 'charmap' codec` | Windows runner 控制台是 cp1252，脚本里有中文日志 | `build_app.py` 启动时 `sys.stdout.reconfigure(encoding="utf-8")`；workflow 设 `PYTHONIOENCODING` / `PYTHONUTF8` |
| `ModuleNotFoundError: No module named 'PIL'` | `tools/make_icon.py` 依赖 Pillow，CI 没装 | 图标已入库则直接复用；workflow 仍补装 `pillow` 兜底 |

自己加构建步骤时记住这条：**Windows runner 的默认编码不是 UTF-8**，任何打印中文的脚本都要显式设置。

## 五、分发给别人

打包好的 zip 直接发就行，但要提前说清三件事：

1. **未签名**，SmartScreen 会拦：点「更多信息 → 仍要运行」
2. **不要解压到 `C:\Program Files`**，那里没有写权限
3. **没 Key 时默认 MOCK**，看到占位画面不是坏了

建议随包附一句：「双击 exe → 等 5 秒 → 新建项目 → 勾 MOCK → 一键成片」。

## 六、体积构成

| 部分 | 体积 |
|---|---|
| `_internal`（Python 运行时 + 依赖 + ffmpeg） | ~130 MB |
| `VisionForge.exe` | 8 MB |
| 压缩后 | ~58 MB |

想瘦身：排除 `edge-tts`、`websocket-client` 等可选依赖，或用 `--onefile`（启动会慢，且每次解压到临时目录）。当前 onedir 是「启动快、体积大」的取舍。

## 七、Mac / Linux

代码本身跨平台（FastAPI + pywebview + ffmpeg），但 `build_app.py` 与 spec 是 Windows 专用的（图标 `.ico`、版本资源、`windowed` 参数）。要出 macOS 包需要：

- 换 `.icns` 图标
- spec 去掉 `version=` 与 `icon` 的 `.ico`
- 用 `py2app` 或 PyInstaller 的 `--windowed` 直接打

CI 目前只跑 Windows 构建，因为这是主要交付形态。
