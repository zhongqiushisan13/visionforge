# 03 模型配置

VisionForge 有四个能力槽：**剧本（LLM）**、**关键帧（图像）**、**镜头（视频）**、**配音（TTS）**。每个槽都能独立选云端或本地，互不绑定。

配置改完点「保存设置」。API Key 默认写入用户目录（Windows：`%APPDATA%\VisionForge\.env`；macOS/Linux：`~/.config/visionforge/.env`），老版本放在 exe 旁边的 `.env` 仍会兼容读取。改完建议重启应用，让服务端重新加载。

## 一、判断当前状态

设置页右上角「系统自检」会列出：

- 剧本大脑：云端就绪 / 本地 / 未配置
- 镜头来源：当前模式与地址
- ComfyUI：在线 / 未连接
- 编码器：实际可用列表

点「测通道」会真发一次请求，比看配置项靠谱。

## 1.1 本地 API 防护与预算

从 v1.1.1 起，本机服务默认开启三道保护：

1. **Token**：启动时生成随机 token 写入 `run/token`，页面由服务端注入；所有 `/api/*` 请求都要带 `X-VF-Token`
2. **Host 校验**：只接受 `127.0.0.1` / `localhost` / `[::1]`，防 DNS rebinding
3. **不启用 CORS**：前后端同源，跨源网页默认拿不到任何项目数据，也不能替你点「一键成片」

媒体文件走同源 Cookie / token 查询参数授权；`/api/health` 是唯一公开探活接口，只返回版本号。

预算护栏在设置页配置（或环境变量）：

```env
VF_BUDGET=20       # 单项目估算成本上限，元；0=不限
# 需要校准价格时：
# VF_PRICES={"deepseek":0.05,"minimax_video":3.0,"minimax_tts":0.1}
```

每次真实付费调用（DeepSeek 剧本、MiniMax 视频、MiniMax TTS）都会写进 `project.json` 的 `meta.costs`；超出上限会在**调用前**阻断并在界面弹错。成片页可导出「成本小结」文本。本地 Ollama / ComfyUI / MOCK 通道记 0 元。

## 二、剧本（LLM）

任何 OpenAI 兼容接口都能用，因为只依赖 `/chat/completions` 和 `response_format={"type":"json_object"}`。

### 云端（DeepSeek）

```env
DEEPSEEK_MODE=cloud
DEEPSEEK_API_KEY=sk-xxxxxxxx
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash
```

### 本地（Ollama 为例）

```bash
ollama pull qwen2.5:14b
```

```env
DEEPSEEK_MODE=local
DEEPSEEK_BASE_URL=http://127.0.0.1:11434/v1
DEEPSEEK_MODEL=qwen2.5:14b
# API Key 留空即可
```

本地服务不校验 Key 时不要填假值——代码只在有 Key 时才带 `Authorization` 头。

### 模型不支持 JSON 模式怎么办

不用管。客户端有三层兜底：JSON 模式 → 从自由文本里扫平衡括号抽 JSON → 换备用模型 → 最后用内置示例分镜。会慢一点，但不会卡死。

## 三、关键帧（ComfyUI）

```env
COMFYUI_BASE_URL=http://127.0.0.1:8188
COMFYUI_WORKFLOW=txt2img_api.json
COMFYUI_DEFAULT_LORA=style_v3.safetensors
COMFYUI_LORA_STRENGTH=0.75
```

工作流文件放在 `workflows/` 下（打包版在 `_internal/workflows/`，也可以在 exe 同级建 `workflows/` 覆盖）。

**LoRA 不用手改工作流**：程序会遍历节点图，找到 checkpoint 加载节点，插入一个 `LoraLoader`，把它所有下游消费者重定向过去。你原来的工作流不需要动。

节点识别规则：

| 用途 | 识别方式 |
|---|---|
| 正向提示词 | 节点标题含 `POSITIVE` / `positive` |
| 负向提示词 | 标题含 `NEGATIVE` |
| 分辨率 | 节点输入里有 `width` + `height` |
| 采样器 | 类名 `KSampler` / `KSamplerAdvanced` |

设置页点「检测」会读回 ComfyUI 的 checkpoint 与 LoRA 列表，点一下就填进输入框。

## 四、镜头（视频）

四种模式，按需选：

### 1. 云端 MiniMax H3

```env
MINIMAX_MODE=cloud
MINIMAX_API_KEY=xxxxx
MINIMAX_VIDEO_MODEL=MiniMax-H3
MINIMAX_RESOLUTION=768P
MINIMAX_RATIO=16:9
```

流程是异步任务：提交拿 `task_id` → 轮询状态 → 下载结果。错误码会被翻译成中文提示（限额、内容审核、参数错误等）。

### 2. 本地兼容网关（免 Key）

只要你的服务实现两个接口：

```http
POST {base}/v2/video_generation
{ "model": "MiniMax-H3",
  "content": [{"type":"text","text":"..."},
              {"type":"image_url","image_url":{"url":"data:image/png;base64,..."},"role":"first_frame"}],
  "duration": 6, "resolution": "768P", "ratio": "16:9" }
→ { "task_id": "xxx" }

GET {base}/v2/query/video_generation/{task_id}
→ { "task": { "status": "succeeded", "content": { "url": "http://.../out.mp4" } } }
```

```env
MINIMAX_MODE=local
MINIMAX_BASE_URL=http://127.0.0.1:8000
```

协议形状不一样也没关系，设置页可以改提交/查询路径。想先验证连通性，仓库里有 mock 服务：

```bash
python tools/mock_h3_server.py --port 8798 --video 某个现成mp4
MINIMAX_MODE=local MINIMAX_BASE_URL=http://127.0.0.1:8798 python run_app.py
```

### 3. ComfyUI 视频工作流

```env
MINIMAX_MODE=comfyui
MINIMAX_VIDEO_WORKFLOW=wan21_i2v.json
MINIMAX_VIDEO_TIMEOUT=3600
```

工作流的节点标题按这套约定写，适配器才找得到：

| 标题 | 作用 |
|---|---|
| `POSITIVE` / `NEGATIVE` | 提示词 |
| `LOAD_IMAGE` | 首帧图（会自动上传） |
| 含 `width` + `height` | 分辨率 |
| 含 `length` / `num_frames` / `video_frames` | 帧数 = 时长 × fps |
| 输出节点 `SaveVideo` / `VHS_VideoCombine` | 产物（`gifs` 里的 mp4 也认） |

适配器对提示词字段是**两种都认**的：SD/SVD 系用 `text`，MiniMax H3 的
`MiniMaxH3ImageToVideo` 用 `prompt`；`CreateVideo` 的 `fps` 也会被同步成成片帧率
（不同步会出现「24fps 拍的片子按 8fps 播」这种慢放）。

### 3.1 MiniMax H3 本地量化版（GGUF，8GB 显存可跑）

官方权重 33B，全精度要 4 卡；本地用社区剪枝 + GGUF 量化，仓库自带
`workflows/minimax_h3_gguf_i2v.json`（API 格式，14 个节点），装上模型即可用：

| 放到 | 文件 | 体积 | 来源 |
|---|---|---|---|
| `models/diffusion_models/` | `minimax_h3_fl2va_pruned-Q2_K.gguf` | 6.7 GB | `unsloth/MiniMax-H3-GGUF` |
| `models/text_encoders/` | `qwen3vl_32b_minimax_h3-Q2_K_M.gguf` | 13.1 GB | 同上 |
| `models/vae/` | `minimax_h3_video_vae_fp16.safetensors` | 5.2 GB | `Abiray/MiniMax-H3-GGUF` |
| `models/loras/` | `minimax_h3_fl2v_turbo_4step_v1.0_768p_comfyui_bf16.safetensors` | 2.0 GB | `Comfy-Org/MiniMax-H3` |

前置条件：

1. ComfyUI ≥ 0.30（H3 节点是内置的：`MiniMaxH3ImageToVideo` 等）
2. 装 `ComfyUI-GGUF` 自定义节点，并 `pip install gguf`（缺这个库节点会 IMPORT FAILED）

```env
MINIMAX_MODE=comfyui
MINIMAX_VIDEO_WORKFLOW=minimax_h3_gguf_i2v.json
MINIMAX_VIDEO_TIMEOUT=5400
COMFYUI_BASE_URL=http://127.0.0.1:8188
COMFYUI_WIDTH=608          # 8GB 显存的安全档，且必须是 32 的倍数
COMFYUI_HEIGHT=352
VF_FPS=24                  # H3 原生 24fps，别留 30
VF_WORKERS=1               # 显存不够时并发只会互相挤爆
```

ComfyUI 启动建议带 `--lowvram`。8GB 显存 + 4 步 Turbo LoRA 的实测预期：
608×352、约 5 秒一条，单条分钟级；想要 768p 请上 24GB 卡或走云端 API。
首次加载文本编码器（Qwen3-VL-32B）会吃满内存并大量换页，属于正常现象。

### 4. 占位（mock）

`MINIMAX_MODE=mock` 或全局 `VF_MOCK=1`。用 ffmpeg 生成渐变色片段，用于验证流程，**不是真画面**。

## 五、配音（TTS）

三级兜底，不需要单独配置：

1. MiniMax T2A（有 `MINIMAX_API_KEY` 时优先）
2. edge-tts（免费，需要联网）
3. 静音轨（离线兜底，保证时间轴闭合）

音色在设置页改 `voice_id`。edge-tts 走系统联网，不需要 Key。

## 六、推荐组合

| 场景 | 剧本 | 关键帧 | 镜头 | 配音 |
|---|---|---|---|---|
| 零成本试跑 | 示例分镜 | 占位图 | 占位片 | 静音 |
| 预算优先 | Ollama | ComfyUI | ComfyUI 视频 | edge-tts |
| 质量优先 | DeepSeek | ComfyUI + LoRA | MiniMax H3 | MiniMax T2A |
| 隐私优先 | 本地 LLM | 本地 ComfyUI | 本地网关 | edge-tts（仅语音外发） |

注意 edge-tts 会把台词发到微软服务器，纯离线场景请用静音或本地 TTS 替换。
