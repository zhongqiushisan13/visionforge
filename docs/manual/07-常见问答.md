# 07 常见问答

## 它能不能替代剪映？

不能，也不打算。剪映的核心是**图层树 + 关键帧曲线**，能表达"画中画 + 蒙版 + 花字 + 卡点"这种复合结构；VisionForge 是**单轨序列 + 逐镜头参数**，强项是把"零素材"推进到"有素材、有结构、有初版"。

合理分工：VisionForge 出初版，剪映做精修。真要做精修，把素材导出去剪映更划算。

## 需要显卡吗？

不需要也能跑：

- 只接云端 API：CPU 够用，瓶颈在网络
- 全本地：要 N 卡（8GB 显存起步跑视频模型），否则出片速度会很感人

本项目的参考机器是 4 核 / 8GB / 无独显，跑 MOCK 全链路 44 秒成片约 85 秒合成——能用，但别指望它跑真模型。

## 一定要 API Key 吗？

不一定。四个能力槽都能本地方案：

| 槽 | 本地替代 |
|---|---|
| 剧本 | Ollama / vLLM / LM Studio |
| 关键帧 | ComfyUI + LoRA |
| 镜头 | 本地 H3 兼容网关 / ComfyUI 视频工作流 |
| 配音 | edge-tts（免费，需联网） |

全本地时唯一的外发是 edge-tts 的台词文本；纯离线就用静音轨。

## 出片质量取决于什么？

三个因素，按影响排序：

1. **视频模型**（占位片 ↔ H3 是天壤之别）
2. **分镜质量**（LLM 的理解力 + 你给的 brief 具体程度）
3. **剪辑参数**（转场、调色、节奏）

系统能保证的是流程正确、结构完整、字幕对齐；画面好不好看，取决于你接的模型。

## 支持竖屏吗？

支持。新建项目时选画幅（16:9 / 9:16 / 1:1），渲染分辨率会跟着变。竖屏建议：

- 镜头时长压短（2~4 秒），节奏更快
- 字幕字号调大
- 标题放顶部（避免和底部字幕打架）

## 能出多长的片子？

技术上没有硬限制，实践上建议：

- 单次 40~90 秒最稳
- 超过 3 分钟，分镜容易散、重跑成本高
- 长片策略：分段生产 → 各自出片 → 用外部工具拼接

## 商用可以吗？

MIT 协议，商用、二改、闭源分发都行，保留版权声明即可。但注意：

- 生成内容的版权与平台合规由使用者负责
- 模型服务商的条款另算（例如某些模型禁止生成真人肖像）
- 不要用它做深度伪造

## 数据会上传到哪？

默认只在本机：服务只监听 `127.0.0.1`，工程文件、素材、成片都在本地磁盘。v1.1.1 起，本机 API 还要求随机 token 与 Host 校验，媒体文件也需要同源 Cookie；这不是云端账号体系，只是防止浏览器里的任意网页偷偷调用本机服务。

会外发的只有你显式配置的服务：LLM 的提示词、视频模型的提示词与首帧图、TTS 的台词。没配 Key 时一个字节都不出去。

## 怎么更新？

- 打包版：下新版 zip 解压到新目录，把旧目录的 `projects/` 拷过去；API Key 默认在用户目录（`%APPDATA%\VisionForge\.env`），通常不用搬
- 源码版：`git pull && pip install -r requirements.txt`
- 配置兼容：`config.json` 缺字段会用默认值补齐，一般不用手动改

## 为什么没有自动更新？

因为它是绿色版，没有安装器、没有注册表、没有常驻服务。想更新就覆盖文件，想删就删目录——这是设计取舍，不是没做完。

## 为什么不支持多轨 / 蒙版 / 关键帧？

这些需要图层树和关键帧曲线，属于重写渲染器的量级。硬塞几个假按钮，只会让你在导出时发现"怎么不起作用"。更实际的方向是导出 EDL/XML 给专业 NLE，而不是在本地重造一个半成品。

## 遇到 bug 怎么办？

先看 [06 故障排查](06-故障排查.md)，再开 issue 并附：系统版本、`logs/runtime.log` 最后 50 行、复现步骤、系统自检截图。
